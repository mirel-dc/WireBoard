# Wireboard

Локальная библиотека хранится в `%LOCALAPPDATA%\Wireboard` на Windows, `~/Library/Application Support/Wireboard` на macOS и `$XDG_DATA_HOME/wireboard` либо `~/.local/share/wireboard` на Linux. `WIREBOARD_DATA_DIR` или `--data-dir` выбирают другой каталог. Каждый файл `boards/<id>.json` содержит одну доску, её слайды, комментарии и историю. Docker монтирует тот же каталог в `/data`; Node.js для работы приложения не нужен.

Обычный localhost открывает библиотеку без входа и одноразовых ссылок. Доски открываются слева или по постоянному адресу `/b/<slug>`. `boards` возвращает внутренний `id` и читаемый `slug`; для CLI-изменений используй `id`, пользователю передавай ссылку со `slug`. Возьми адрес сервера из `open --print-url` и добавь `b/<slug>` к корневому URL. Не угадывай slug по названию: кириллица транслитерируется, одинаковые названия получают суффиксы. При переименовании адрес сохраняется; старое `/?board=<id>` тоже работает и превращается в читаемую ссылку.

`links.json` — служебный индекс постоянных адресов, включая зарезервированные адреса удалённых досок. Сохраняй его вместе с библиотекой при резервном копировании. JSON-хранилище и индекс не редактируй напрямую. Один сервер обслуживает библиотеку; Docker и native не запускай одновременно с одним каталогом. После аварии с оставшейся `.library-lock` сначала убедись, что все серверы этой библиотеки остановлены; не снимай блокировку с работающего сервера.

Если пользователь просит «разбери открытые комментарии», прочитай [общую инструкцию для Codex и Claude](../../docs/agents/wireboard-comments.md). Выполни `comments <id> --status open`, проверь контекст и текущую revision. Сохраняй изменения схемы и `comment_reply` в одном atomic apply, укажи своего автора (`codex` или `claude`) и обязательный `submitForReview`. Не закрывай обсуждение за пользователя и не запускай обработку самостоятельно без поручения.

Если приложение запущено через Docker Compose, работай из корня проекта через `just cli <command>` вместо native binary. Сначала `just ps` и `just cli boards`. Входной JSON сохрани на компьютере, затем `just upload <absolute-host-file> /data/operations.json` и `just cli apply <id> --revision <revision> --file /data/operations.json`. Экспорт/рендер запиши в `/data/slide.png`, затем `just download /data/slide.png <absolute-host-file>` и посмотри локальное изображение. Пути CLI относятся к контейнеру; файлы в `/data` сохраняются вместе с досками. Не перезаписывай `runtime.json`, `.lock`, `.library-lock`, `links.json` или `boards/*.json` при передаче файлов. `/tmp` — tmpfs, для `docker compose cp` используй `/data`. `just up` запускает сервис, `just open` открывает браузер, `just down` останавливает без удаления досок. `open --print-url` возвращает обычный локальный адрес без секретов. Не читай runtime без необходимости.

Работай с запущенным локальным Wireboard. Найди `wireboard.exe` на Windows или `wireboard` на macOS/Linux: рядом с этим комплектом, в PATH или в `target/release` проекта. Используй абсолютный путь и правильное имя бинарника. При нестандартном каталоге добавляй `--data-dir <root>` во все команды. Node.js приложению не нужен.

1. Выполни `wireboard boards`, выбери нужную доску по названию и сохрани её `id` и `slug`. Если задача не определяет доску однозначно, уточни; не изменяй первую случайную доску.
2. Выполни `wireboard inspect <id>`. Прочитай `revision`, `nextId`, объекты и координаты. При добавлении в существующий слайд сохрани соседние объекты.
3. Создай UTF-8 JSON-файл с массивом операций. Выполни `wireboard apply <id> --revision <revision> --file <absolute-file>`; `--file -` читает stdin. Избегай сложного JSON прямо в командной строке, особенно PowerShell.
4. Проверь возвращённые `revision` и объекты. Выполни `wireboard render <id> --frame <frame-id> --output <absolute-file.png>` и посмотри изображение. Для всей доски опусти `--frame`. Не утверждай, что проверил внешний вид, если лишь получил JSON.
5. Экспортируй переносимый документ при необходимости: `wireboard export <id> --output <absolute-file.json>`.

Операции: `create` с `element`; `update` с `id` и `patch`; `move` с `ids`, `dx`, `dy`; `resize` с `id`, `width`, `height`; `delete` с `ids`; `duplicate` с `ids`, `dx`, `dy`; `rename` с `title`. Весь пакет атомарен; собственное Undo учитывает только команды источника user с ID и actor. Типы объектов: `rectangle`, `text`, `connector`, `frame`, `image`. Связь задаётся `from`, `to`, необязательными `fromPort`/`toPort` (`auto`, `left`, `right`, `top`, `bottom`) и `text`.

Для стиля C разделяй короткий `title` и описание `text`, обычно `fontSize:16`; новая карточка 220×112, под длинное описание увеличь высоту. Текст блоков центрируется; для свободных пояснений используй `kind:text`. Цветом обозначай роль, которую обсуждали с пользователем: голубой `fill:#e0ecf8/stroke:#90abc7`, тёплый `#fff0b8/#ccad49`, мятный `#e0f0e8/#91b4a2`, сиреневый `#eee5f8/#ae91c5`. Оставляй место для подписи между блоками: для «редактируете» при 16px промежуток около 150px. Связи подписывай кратко, обычно `fontSize:16`, `fontWeight:400`. После render убедись, что текст полностью читается и блоки не перекрывают подписи.

Для связи между новыми объектами назначай последовательные ID начиная ровно с `nextId`. Можно опустить ID для автоматического выделения, если остальные операции не ссылаются на новый объект. Пример `examples/agent-slide.json` рассчитан на пустую доску с nextId=1; для существующей доски пересчитай все ID и ссылки.

При конфликте (код `conflict`, HTTP 409) снова прочитай доску и пересмотри операции. Не повторяй изменяющую команду вслепую. При ошибке сохранения прекрати изменение; неопределённый результат записи требует перезапуска сервера и проверки сохранённой доски. CLI не изменяет рабочие JSON напрямую и не печатает токен.

Лимиты: 100 операций в пакете, 2000 объектов, координаты ±100000, размер 20–10000 px, текст 10000 символов, JSON 32 MiB, PNG/JPEG/WebP 8 MiB и 16 млн пикселей. Фрейм свободного размера; переносит явно принадлежащих детей (`parentFrameId`), даже вне рамки. Resize меняет только границы. Пресет 960×540 даёт PNG 1920×1080; свободный фрейм сохраняет пропорции; для очень большой доски используй SVG.

Если сервер выключен, скажи об этом и запусти `wireboard serve --open` при наличии разрешения пользователя на запуск. Если сервер уже работает, выполни `wireboard open` или открой обычный localhost. Доску выбирай слева либо по ссылке `/b/<slug>`; браузеры используют общие серверные файлы. Глобальные настройки Codex и установку этого skill меняй только по отдельной просьбе.

### ID команд и история

Для каждой новой агентской записи генерируй UUID и добавляй к apply `--command-id UUID --actor-id SESSION --author codex` (или claude). Весь batch, включая comment_reply, имеет одного автора. CLI записывает неизменяемый запрос в data-dir/requests перед отправкой. При потере ответа проверь `command BOARD_ID UUID`; если квитанции нет, повтори исходную команду с теми же ID, revision, actor, author и байтами файла. Не подменяй revision при таком повторе. Конфликт требует нового чтения и нового осмысленного действия с новым ID, а не автоматического перезаписывания.

Собственное Undo браузера не отменяет агентские действия. CLI history требует author:user, того же actor-id и конкретного target-command-id из истории. Независимые изменения текста сохраняются; изменение того же поля вызывает конфликт по value и stamp.

У элемента `parentFrameId` — явная принадлежность. Чтобы освободить его, отправь update patch с `parentFrameId:null`. Resize не меняет принадлежность; обычный delete фрейма освобождает детей, delete явного subtree удаляет их. При импорте старого JSON принадлежность выводится один раз. Не правь envelope/history/stamps/receipts напрямую.
